Hands-on

Six walkthroughs

Each walkthrough maps a real user goal to the screens and API calls that complete it. Expand one to follow the steps.

1 Author, type and run your first test case ⌄

Goal: go from a blank workspace to a passing run with screenshot evidence on every step.

  1. Open Test Cases and choose New Test Case. Pick AI Assistance, Import, Record or Manual.
  2. Select one of the 11 test types in the Test Type field (Functional is the default), choose the module and priority, then create.
  3. Open the case in Test Studio. Confirm the Navigate step points at your real URL and add Click, Enter Text or AI Assertion steps.
  4. Click Run. QASyn resolves the target URL, executes each step, and writes a scoped TestCaseRun.
  5. Open Step Details or Run history and confirm the screenshot thumbnail is present for every executed step.
  6. Click any thumbnail to open the Visual Evidence Lightbox: status, MIME badge, timestamp, 🔀 Compare with Previous Run time travel and ⬇ Download Evidence.
Evidence is persisted twice: on stepsJson[i].screenshotBase64 and in the run’s logJson. The Type column always shows the exact type you chose.
2 Ground a selector and recover it with self-heal ⌄

Goal: fix a broken or empty selector without guessing CSS.

  1. In Test Studio, select the failing step and open Step Details.
  2. Click Run Bivia Visual Grounding. QASyn uses the step URL, then variables.url / targetUrl / baseUrl, then the first Navigate target, then the org website.
  3. Review the returned bounding box, confidence and screenshot.
  4. Click Simulate Self-Healing. Bivia proposes a new selector; QASyn persists it on the step, writes a version entry and creates an “Auto-fix rerun”.
  5. Confirm the healed screenshot card and the updated run history show the new evidence.
  6. Click the healed or step thumbnail to open the Visual Evidence Lightbox and compare the previous vs latest run side by side with the opacity slider.
If the target site is unreachable, grounding still returns generated visual evidence and explains whether the DOM/screenshot was live or synthetic.
3 Turn a crawl into a regression suite ⌄

Goal: build a reusable baseline from a deployed application.

  1. Open Crawl and launch a crawl for the target URL (or use Quality Autopilot from Overview/Crawl for the full five-phase flow).
  2. Wait for the crawl to complete. QASyn records flows as requirements and generates linked draft test cases.
  3. Open Test Cases, filter the Type or Module columns, and review the generated cases.
  4. Create a Test Suite, add the cases, then create a Test Plan that binds the suite to an environment and schedule.
  5. Run the plan and inspect the run matrix; every case keeps its own per-step evidence.
Re-importing the same crawl updates the existing linked cases instead of creating duplicates.
4 Gate a pull request and run auto-regression ⌄

Goal: decide whether a PR is safe to merge using impacted tests and a deployed environment.

  1. Open Pull requests and analyse a PR (or open an existing row). Changed files are mapped to modules and impacted cases.
  2. In the drawer, click Generate CI/CD PR Gate Comment. Review the verdict, Bivia risk score, impacted test table and Strix security summary, then copy the Markdown.
  3. In the PR auto-regression section, choose the environment (Production, Staging or any configured environment) or override the deployed URL.
  4. Keep Auto-create PR-specific test cases checked. QASyn creates a Smoke and a Regression case named PR #n · … if none exist.
  5. Click Run PR auto-regression. The result panel shows pass/fail/regressions, the target URL and the created cases; the PR row updates its verdict and counts.
A caught regression sets the PR to regression_caught. Open the affected case → run history to inspect the failing step’s screenshot before merging.
5 Provision and configure an enterprise tenant ⌄

Goal: onboard a new customer without touching SQL or the database console.

  1. Sign in as the super admin and open Settings → Organization → Super-Admin Console (or use the workspace menu).
  2. Click Provision enterprise. Fill in organisation, website, admin name/e-mail/password, seats, environment name/URL and credits.
  3. Submit. In one transaction QASyn creates the Enterprise organisation, Production + Staging environments, a credit ledger grant, a verified Admin user and an audit entry.
  4. Use the per-organisation Configure action to change plan, grant credits, update seats/environment and toggle SSO/SLA.
  5. Switch into the new workspace from the sidebar to verify its environments, billing and team.
Enterprise defaults to 250,000 credits. The ledger grant is visible in Billing & usage and the admin can sign in immediately.
6 Filter, export and operate with confidence ⌄

Goal: find the exact rows you need and share evidence with the team.

  1. On any data grid (Test Cases, Crawl, Requirements, Suites, Plans, Team, Audits, Pull Requests), click the filter icon in a column header.
  2. Categorical columns such as Type, Status or Priority offer a distinct-value dropdown; dates and text accept a substring search.
  3. The filter icon shows a blue dot when active. Reopen it and choose Clear, or use the toolbar filter chips, to reset.
  4. Select rows to reveal the bulk bar: run selected, export CSV or delete (permission-dependent).
  5. For operational context, open Billing & usage for credits and the Bivia observatory, Integrations for providers, or MCP to query the workspace from an assistant.
Existing search, column visibility, pagination and RowMenu actions stay available — per-column filters are additive.

Architecture & API

QASyn is a Next.js App Router application. Server components read Prisma directly; client workspaces call authenticated route handlers. The execution engine is the only layer that launches Playwright.

PresentationMarketing, onboarding, dashboard modules, Test Studio, this guide.
ApplicationRoute handlers in app/api/dashboard/* with Zod validation and RBAC guards.
Domainengine.ts, web-executor.ts, selector-healing.ts, bivia.ts, pr-gate.ts.
PersistencePrisma Client over SQLite: organisations, users, cases, runs, suites, plans, PRs, environments, credits, audits.
ExternalArticul8 Bivia, GitHub/GitLab, Jira/Linear, Slack, browser providers, Strix.

Run pipeline

request → RBAC → URL resolver → Playwright per step → Bivia assertion/heal → screenshot evidence → TestCaseRun.logJson → Studio UI

Evidence model

Each step stores screenshotBase64 + screenshotMime. Runs store the same fields per log line. The UI falls back from the step to the latest run, so no executed step shows an empty placeholder.

Grounding priority

detailStep URL → variables.url/targetUrl/baseUrl → first Navigate step → orgUrl

All endpoints are same-origin and session-authenticated. Send JSON with content-type: application/json.

GET/api/dashboard/test-cases

List cases with steps, variables and run metadata.

POST/api/dashboard/test-cases

Create a manual or AI case. Include testType to persist one of the 11 types.

{ "mode": "manual", "title": "Checkout", "module": "Checkout",
  "criticality": "high", "stepsCount": 5,
  "testType": "Regression", "targetUrl": "https://staging.example.com" }
PATCH/api/dashboard/test-cases/[id]

Actions: steps, run_steps, simulate_self_heal, metadata updates. Returns run log with per-step screenshots.

POST/api/dashboard/bivia/ground

Ground a target description on a URL. Returns screenshotBase64, DOM status and a normalized bounding box.

{ "targetDescription": "Sign in button",
  "targetUrl": "https://staging.example.com/login" }
POST/api/dashboard/pull-requests/gate

Generate the CI/CD Markdown gate report for a stored pull request.

{ "id": "pr_check_id" }
POST/api/dashboard/pull-requests/auto-regression

Run impacted + PR-specific cases against the deployed URL with deterministic outcomes.

{ "id": "pr_check_id",
  "environmentId": "env_id",
  "targetUrl": "https://staging.example.com",
  "createTests": true }
GET/api/dashboard/qasyn/workflows

QASyn Agent workflow history. POST runs the crawl → generate → execute → report pipeline with a Go / No-Go decision.

POST/api/dashboard/qasyn/pr-impact

Map changed files to modules, select the regression scope and return the Go / No-Go verdict and blast radius.

{ "prNumber": 1234, "branch": "main", "title": "Fix checkout", "files": ["src/checkout/page.tsx"] }
POST/api/dashboard/qasyn/bug-repro

Turn a support ticket into reproduction steps, a bug report and a generated test case with a probable root cause.

POST/api/webhooks/ci-pr

Autonomous CI/CD gatekeeper for GitHub Actions, GitLab CI and Azure DevOps. Authenticate with x-qasyn-token: cqa_…, Authorization: Bearer cqa_… or a session cookie. Upserts the PR, auto-creates Smoke + Regression cases, runs the suite with per-step screenshots and returns verdict + markdownReport. Set failOnRegression: true for HTTP 422 on regressions.

{ "prNumber": 402, "title": "Feat: BDC loan calculator",
  "branch": "feat/loan-calculator", "branchTarget": "main",
  "author": "ci-bot", "repository": "org/web-portal",
  "changedFiles": ["src/checkout/loan.ts"],
  "previewUrl": "https://www.bdc.ca",
  "environmentName": "Staging",
  "createTests": true, "failOnRegression": false }
POST/api/dashboard/super-admin

Enterprise provisioning and configuration.

{ "action": "create_enterprise_tenant",
  "organisationName": "Acme Enterprise",

List environment configs; the default environment is used by PR auto-regression when no ID is supplied.
